# Lab 3.2 캡스톤 제출

**1. 어떤 문서로 만들었나**

학사운영 규정 발췌본(`학칙.md`, 1,005자). RECURSIVE / chunkSize 400으로 인덱싱해 청크 4개입니다.

**2. 어떤 티어까지 했고, 무엇을 구현했나**

`StudentRagPipeline.java`의 훅 네 개를 전부 채웠습니다 (실버 셋 + 골드 b).
`rewriteQueries` 질문 재작성 · `keywordSearch` TF-IDF 하이브리드 검색 · `rerank` LLM 재정렬 ·
`selfCheck` 자기 검증. 커밋은 단계별로 하나씩 나눠 두었습니다.

자유 확장(§4)도 여섯 항목을 전부 했습니다.

| 항목 | 한 일 | 확인 |
|---|---|---|
| 파이프라인 새로 쓰기 | `DecomposeRagPipeline` — `RagPipeline` 직접 구현, 질문을 하위 질문으로 쪼개 각각 검색 | `@Component`만으로 드롭다운 자동 등록 |
| 새 이벤트 타입 | 하위 질문별 검색 점수를 `subQuery` 이벤트로 방출 | 프론트 수정 없이 인스펙터 로그 탭에 표시 |
| 청킹 전략 추가 | `SEMANTIC` — 문장 임베딩 유사도가 급락하는 지점에서 분할 | 같은 문서가 4청크 → 11청크(평균 88자) |
| 인덱스 영속화 | `SimpleVectorStore.save/load` + 문서 메타·청크 JSON | 재시작 후 재업로드 없이 복원, 키워드 검색도 정상 |
| PGVector 교체 | Maven `-Ppgvector` + Spring `pgvector` 프로필 | `day3_vectors` 테이블에 4행 확인, 파일 영속화는 자동으로 꺼짐 |
| 프론트 손보기 | `부가 N초` 지표 배지, 근거 채택순/유사도순 토글 | 43.3초 중 28.3초가 부가 단계임이 화면에 보임 |

**3. 어디서 막혔나 / 무엇이 의외였나**

- **재작성이 기본 설정에서 답을 못 바꿉니다.** `mergeDistinct`가 쿼리 순서대로 결과를 이어붙이고
  `finalizeSources`가 앞에서 topK개만 자릅니다. 원문 쿼리 결과가 앞자리를 다 차지해서 재작성이
  찾은 청크는 잘려나갑니다. 유사도 임계값을 올리거나 재정렬을 같이 켜야 효과가 보입니다.
- **자기 검증이 할루시네이션을 못 잡습니다.** 근거에 없는 금액과 날짜를 일부러 섞은 답변에
  `통과`가 나왔습니다. 프롬프트를 세 가지로 바꿔봤지만 llama3.2:3b로는 판별이 되지 않았습니다.
  배관은 동작하는데 판정을 믿을 수 없습니다.
- **프롬프트에 적은 예시를 모델이 그대로 베껴 옵니다.** 지시어를 `"그거", "거기"`처럼 따옴표
  예시로 보여줬더니 재작성 결과에 그 따옴표가 딸려 나왔습니다. 규칙 문장으로만 적으니 사라졌습니다.
- **질의 분해를 시키면 모델이 답을 지어냅니다.** 쪼개라고 했는데 `근로장학금은 시간당 1,000원입니다`
  같은 문장을 뱉었고 그게 검색 쿼리로 나갔습니다. 물음표로 끝나지 않는 줄을 버리도록 막았습니다.
- **`@ConditionalOnMissingBean`은 자동설정보다 먼저 평가됩니다.** PGVector를 붙일 때 이걸로 기본
  스토어를 조건부로 만들었더니 빈이 둘 다 생겨 기동에 실패했습니다. `@Profile("!pgvector")`로 바꿨습니다.

네 토글을 전부 켜면 43.3초, 기본 RAG는 같은 질문에 6.3초입니다. 청크가 4개뿐이라 정답은 같습니다.
넷 중 키워드 검색만 LLM을 쓰지 않아 3ms로 사실상 공짜입니다.
