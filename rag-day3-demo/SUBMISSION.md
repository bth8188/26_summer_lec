# Day3 캡스톤 제출

## 사용한 문서
- `2026_guidebook_KR.pdf` — 서울 관광안내서 (50페이지)
- `유니버설 관광 거버넌스 통합 가이드북_국문_최종.pdf` — 무장애 관광 정보 (51페이지, 서울 외 인천·충남·광주·경북·부산·울산 포함)
- 서버 기동 시 `docs/` 폴더에서 자동 인덱싱 (총 352청크)

## 구현 범위

### 브론즈 (필수)
- 문서 인덱싱, 질문 3개 이상(일반 관광 / 접근성 관광 / 답 없는 질문) 테스트
- 답변 근거 청크·유사도 점수 확인

### 실버 (권장) — `StudentRagPipeline.java`
- `rewriteQueries`: 질문 재작성 / multi-query 검색
- `keywordSearch`: 벡터 + 키워드 하이브리드 검색
- `rerank`: LLM 기반 재정렬(0~10점 채점 후 상위 선택)

### 골드 (도전) — `StudentRagPipeline#selfCheck`
- 생성된 답변이 근거에 실제로 있는 내용인지 LLM으로 재검증

### 추가 구현
- `TourDocumentLoader`: 서버 기동 시 관광 PDF 자동 인덱싱 + 콘솔에 페이지/청크 수 출력
- `AbstractRagPipeline`: 한글이 없는 질문(외국어) 자동 감지 → EN→KO 번역 → 검색/생성 → KO→EN 번역 (인용 번호 유지)

## 막힌 점 / 의외였던 점
- Ollama가 이 컴퓨터 GPU(오래된 드라이버, 2020년)에서 임베딩 중 계속 크래시(`0xc0000005`)가 나서, `OLLAMA_LLM_LIBRARY=cpu`로 강제 전환해서 해결했다. 대신 CPU 모드라 재정렬(rerank)처럼 LLM을 여러 번 호출하는 기능은 몇 분씩 걸린다.
- 관광 PDF가 표·아이콘이 많은 브로슈어 레이아웃이라, 텍스트 추출 시 옆 칸 정보가 섞이는 경우가 있었다(예: 경복궁 항목에 덕수궁 정보 혼입). 재정렬(rerank)을 켜니 이 문제가 줄어들었다.
- 영어 질문을 번역할 때 답변의 인용 번호(`[1]`)가 처음엔 사라졌는데, 번역 프롬프트에 "인용 번호는 그대로 유지하라"는 지시를 추가해서 해결했다.
